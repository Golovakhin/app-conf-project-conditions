## Контекст

Наша команда разрабатывает **CarRentSGM** — приложение для управления арендой автомобилей — в рамках курса «Управление конфигурацией бизнес-приложений».

К началу практики №3 зависимости проекта были описаны в `requirements.txt`, полученном через `pip freeze`. Такой файл не отделяет прямые зависимости от транзитивных, не позволяет проверить согласованность окружения и не воспроизводит сборку один в один.

**Проблема:** выбрать менеджер зависимостей, который позволит:

1. Хранить прямые зависимости проекта в `pyproject.toml`.
2. Фиксировать всё дерево зависимостей в lock-файле.
3. Воспроизводимо ставить окружение и собирать Docker-образ.
4. Быть посильным для команды из 3 человек.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| pip + `requirements.txt` | Знаком всем, ничего не надо ставить | Нет `pyproject.toml` и lock-файла, ручное обновление | Отвергнут: не соответствует результату недели 6 курса |
| Poetry | `pyproject.toml` и `poetry.lock`, зрелый инструмент, экспорт в `requirements.txt` | Нужен плагин `poetry-plugin-export`; у команды нет опыта | Рассмотрен, но отвергнут |
| **uv** | `pyproject.toml` и `uv.lock`, ставится одной командой, быстрый, официальный образ `ghcr.io/astral-sh/uv` | Молодой инструмент | **Выбран** |

## Решение

Используем **uv** как менеджер зависимостей.

### Как ставятся зависимости

- **Разработчик:** `uv sync` создаёт `.venv/` и ставит всё по `uv.lock`. Запуск приложения: `uv run uvicorn main:app --reload`.

- **Dockerfile:**

  ```dockerfile
  COPY --from=ghcr.io/astral-sh/uv:0.13.1 /uv /bin/uv
  COPY pyproject.toml uv.lock ./
  RUN uv sync --locked --no-dev --no-install-project
  ```

  Флаги:
  - `--locked` — образ не соберётся, если `uv.lock` расходится с `pyproject.toml`;
  - `--no-dev` — без dev-зависимостей;
  - `--no-install-project` — ставим только зависимости, без самого проекта.

  **Проверено на практике №3:** образ собирается, `/health` отвечает `{"status":"healthy","database":"ok"}`.

### Версия Python

`.python-version` содержит `3.12` — эта версия используется и локально, и в Dockerfile (`FROM python:3.12-slim`).

## Обоснование

uv даёт одновременно `pyproject.toml` и lock-файл, ставится одной командой на любую ОС и собирает окружение быстрее Poetry. В команде нет опыта с Poetry — учиться на ходу дороже, чем один раз прочитать документацию uv. Результат недели 6 курса (`pyproject.toml` + lock-файл) закрывается uv из коробки.

## Последствия

### Положительные

- Появился `uv.lock` с точными версиями и хешами пакетов.
- Сборка образа воспроизводима: `uv sync --locked` читает `uv.lock` как источник правды.
- Повторная сборка после правки `main.py` показывает `CACHED` на шаге установки зависимостей: первая сборка шла заметно дольше (скачивание образа uv и установка пакетов), повторная — секунды.
- `requirements.txt` удалён: в проекте один источник правды о зависимостях.

### Отрицательные

- Версии в `uv.lock` могут быть новее, чем были в `requirements.txt`: uv берёт последние подходящие. Это нормально и зафиксировано здесь.
- Ещё один инструмент в цепочке: uv должен стоять и на ноутбуке разработчика, и использоваться в Dockerfile.

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Гипотеза для Dockerfile не сработает | — | — | **Не сработал:** команда `uv sync --locked --no-dev` из официального образа `ghcr.io/astral-sh/uv:0.13.1` собирается с первого раза |
| `uv.lock` расходится с `pyproject.toml` | Низкая | Среднее | Флаг `--locked` в Dockerfile и в проверке `uv sync --locked` — сборка/установка падает с ошибкой вместо тихой подмены версий |
| Разные версии Python на ноутбуках команды | Низкая | Среднее | `.python-version` фиксирует 3.12; `uv python install 3.12` ставит нужную версию автоматически |
